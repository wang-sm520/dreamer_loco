# TASK.md — AIRBOT 深度策略：脚本老师 → 深度学生 → 残差 PPO

先读 `AGENTS.md`。本文件前半部分是交接（2026-10-14 第二次更新）：现状、用户已经定下的事、下一步的长程任务（第 6 节 M7–M10）。后半部分是完整的进度记录。旧版交接都在 `airbot_rl/.backup-20261011/`（`TASK.md` 是 10-03 计划，`TASK_20261013.md`、`TASK_20261014.md`、`TASK_20261014b.md` 是之前几版）。

## 1. 目标和路线

- 任务：AIRBOT Play 装在趴着的 M1 狗背上，抓起地上的易拉罐（直径 6.5 cm，高 11.4 cm，重 250 g），再回到起始位置。
- 路线（用户 10-11 定）：在 Isaac Sim 里写一个能读真值的脚本老师；用 DAgger 把它蒸馏成只看深度的学生，学生的网络结构和真机 BC 一样；最后冻结学生，用残差 PPO 微调。
- 干净仿真深度下这条路线已经跑通（M6：学生 93.8%，学生 + PPO 99.6%）。这一轮（用户 10-14 定）只做**仿真稳健性**：腕部深度噪声和几项场景随机化，部署端代码不动，不上真机。

## 2. 框架（`airbot_rl/`，14 个文件，约 1500 行）

| 文件 | 作用 |
|---|---|
| `scene.py` | 场景：狗趴姿、臂、罐子、地毯、墙、头部和腕部相机。还有部署端常量（`LOWER/UPPER/STEP_LENGTH/EXECUTE/COMMAND_DELAY`）、`head_image`（头部渲染图 → 真实相机像素，乘曝光增益 `HEAD_GAIN=0.65`）、`d405_noise`（通用 D405 噪声，参数是 10-11 按常识定的，没实测）。 |
| `env.py` | 唯一的环境 `CanEnv`。`cfg.base="bc"` 时基础策略是冻结的深度网络；`"script"` 时是老师，不渲染相机。`cfg.teacher=True` 时同时算出老师的 8 步标签，蒸馏用。`env.held` 是新的夹住判据，`env.gripped` 是接触判据。 |
| `reward.py` | 分阶段奖励，纯 torch，可以在 CPU 上单测。返回 reward、held、gripped、candidate。 |
| `script.py` | 老师。没有阶段记忆，每一步只看当前状态，用 `env.gripped` 判断"已经夹紧"。 |
| `distill.py` | DAgger 蒸馏。数据全在内存里：每帧约 131 KB，10 万帧约 13 GB。 |
| `ppo.py` | `TRAIN_CFG`（init_std 0.2）、`TimePPO`（按时间折扣）、`load_actor`。 |
| `train.py` | 残差 PPO 训练入口；不加 `--resume` 时 actor 均值层初始化为 0，第 0 轮就等于学生。 |
| `evaluate.py` | 评估，每个环境只算第一回合，可以顺便录像。指标：成功、held/gripped、倒地、碰撞、关节越限、`seconds`、`longest_decision_s`。 |
| `policy.py`、`depth.py` | 冻结的深度网络和 DA2；腕部深度编码。 |
| `assets.py`、`replay.py`、`finetune_bc.py` | 资产生成；旧的腕部深度 BC 训练流程（不用）。 |

一步 = 一次部署决策：

1. 渲染两台相机。头部 RGB 过 DA2，腕部取米制深度，都变成 128×128。学生输入两路深度和 7 维状态，输出 8 个目标，执行前 4 个。
2. 残差 actor 的输入是学生融合层的 512 维特征、归一化状态和学生的 4 个目标，输出 28 维残差（tanh 后乘 0.05 rad / 0.01 m）。critic 看真值。
3. 目标裁剪到关节范围，单步 ≤0.1 rad，关节越限扣分，夹爪只截断。每个目标按 ceil(max|Δ|/0.01 rad) 拆成 25 Hz 插值点，指令延迟 100 ms（`COMMAND_DELAY=10` 个物理步，所有环境共用一个环形队列），物理 100 Hz。
4. 读接触（>1 N：臂碰狗、碰地，手指碰罐），算奖励、成功、倒地。

## 5. 已经查明的问题（摘要，细节看进度记录）

- 夹爪越限扣分会让 PPO 把夹爪收窄去蹭罐（10-14 查明，M6 改成只截断后解决：接近罐子时夹爪残差 −0.61 → +0.05 cm）。
- init_std 0.5 时探索噪声太大，学生加噪声只有约 60% 成功；M6 改 0.2 后 PPO 第一次明显超过学生。
- 学生只会适应训练时见过的深度样式：干净学生怕噪声，噪声学生怕干净。真机 D405 两种都不是。
- PPO 会拉长单次决策（学生 0.36 s → PPO 0.48–0.76 s），部署端 `max_camera_age_s` 是 2.0 s，还有余量。
- 蒸馏每轮学生自己开的成功率会波动 ±7%，挑 checkpoint 要用评估结果，不要看蒸馏日志里那一轮的数。

## 6. 长程任务：M7–M10，仿真稳健性

整体顺序：M7 实现随机化并测基线 → M8 蒸馏稳健学生 → M9 在稳健学生上跑残差 PPO → M10 总表。全程不用问用户，除非遇到下面"停下汇报"的情况。每个里程碑结束在第 9 节进度记录里写结果；正式训练每 100 轮写一行。

**三种评估条件**（之后所有评估都按这三种报）：

- `clean`：全部随机化关闭，和 M6 一样。
- `noise1`：腕部噪声强度固定 1.0，其余随机化关闭。
- `random`：表 3 里的四项随机化全开。

### M7：实现随机化 + 验收 + 基线

代码改动（尽量少，常量和预设只定义一次）：

1. `scene.py`：`d405_noise(depth, strength)`，strength 是 [N] 的张量。strength=0 时原样返回输入（要逐元素完全相等）；strength=1 时和现在的行为一样。按强度线性缩放：尺度误差的标准差（0.01·s）、z² 噪声系数（0.02·s）、深度台阶处置空的概率（0.5·s）、成块空洞的覆盖（阈值 1 − 0.15·s）、散点空洞概率（0.01·s）。`head_image(rgb, gain)` 的 gain 是 [N] 的倍数，乘在 `HEAD_GAIN` 上。
2. `env.py`：`CanEnvCfg` 加四个范围字段（噪声强度、曝光倍数、延迟物理步、罐子抖动），默认值就是现在的固定值（噪声 0、曝光 1、延迟 10、抖动 0.01），这样默认行为不变。复位时每个环境各抽一次存起来。延迟改成每个环境自己的：用长度 ≥13 的历史队列，按 `tick − delay_i` 读，复位时整段填成当前指令。三种评估条件写成一个预设（比如 `CONDITIONS = {"clean": {...}, "noise1": {...}, "random": {...}}`），只在 `env.py` 定义一次。在 `extras["log"]` 里记录抽到的噪声强度、曝光、延迟的均值，确认确实在抽。原来的 `wrist_noise` 开关去掉，由噪声强度范围代替。
3. `evaluate.py`、`distill.py`、`train.py` 加 `--condition clean|noise1|random`（默认 clean），取代 `--wrist_noise`。`evaluate.py` 的输出里写上 condition。

验收（全部通过才往下走；不通过就修代码，修代码不算"试一次"，但改了数值或范围就要停下问用户）：

1. CPU 单测（脚本放 `/tmp/rltest/`）：strength 0 时 `d405_noise` 输出和输入完全相等；strength 0.5/1.0 时空洞比例单调增加，1.0 时和改之前的函数（备份里有）同分布（空洞比例相差 <10%）；head gain 1.0 时 `head_image` 和改之前逐像素相等。
2. clean 条件下行为不变：M6 PPO model_200，clean，seed 0，128 回合，成功 ≥126/128（M6 是 128/128）；学生 round_05 clean seed 0 ≥117/128（M5 复测是 121/128）。
3. 延迟检查：4 个环境，固定延迟分别设 8/10/12 物理步，开环发同一串关节目标，确认关节响应的滞后分别差约 20 ms（看第一次越过目标一半的时刻）。
4. 老师在 random 条件下：seed 0，128 回合，成功 ≥127/128。不到 127 就停下汇报（说明某项随机化让任务本身变难了，范围要用户定）。
5. 4 环境 2 轮的 random 条件 PPO 冒烟和 distill 冒烟（`--rounds 1 --steps 5`）：退出码 0，数值有限，日志里抽到的值分布合理。

基线（不训练，只评估）：学生 round_05、噪声学生 round_03、M6 PPO model_200，各在 clean/noise1/random 三种条件下跑 seed 0 和 seed 1，共 18 次评估。老师在 random 下补 seed 1。结果写成一张表。

### M8：稳健学生蒸馏

- 命令：`distill.py --checkpoint airbot_rl/runs/distill_random_v1/round_05.pt --condition random --output airbot_rl/runs/distill_robust_v1 --num_envs 128 --rounds 6 --steps 2000 --batch 64 --lr 1e-4 --seed 0`（不加 `--random_init`）。
- 开跑前和每轮之间看一下 `free -g`：可用内存 <8 GB 就停下汇报，不要让机器开始用 swap。
- 选模型：round_03/04/05 三个在 random 条件 seed 0 各跑 128 回合，取成功最多的（并列取靠后的）。选中的再跑满 clean/noise1/random × seed 0/1。
- 达标线（用户定）：三种条件各自 ≥218/256（85%）。达标就进 M9。
- 不达标，允许自己再试一次，二选一，在进度记录里写明选哪个、为什么：
  - (a) 从选中的 checkpoint 再跑一次 distill.py（同样的参数，输出 `distill_robust_v2`）。适合三条件都差不多、只是还没练够的情况。
  - (b) 同 (a)，但 lr 改成 3e-5。适合各轮之间成功率上下乱跳、看起来是学习率太大的情况。
  - 选模型和达标判断同上。还不达标就停下汇报，不进 M9。

### 任何时候都要停下汇报的情况

- NaN/inf、Traceback、显存不够、Isaac 卡死且按 PID 杀掉重跑一次还是卡死。
- 可用内存 <8 GB，或磁盘剩余 <30 GB（现在约 100 GB）。
- 老师在 random 条件下 <127/128。
- 需要改任何门限、奖励、判据、超参、随机化范围，或者表 3 没写到的取舍。

### 长任务的跑法

- 每个阶段写成 `/tmp/rltest/m7_*.sh` 这样的流程脚本，nohup 加 setsid 启动，每一步写 status 和 done 文件。
